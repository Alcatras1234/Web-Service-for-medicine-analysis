# EosinAI — бенчмарки производительности

Скрипт `run_benchmarks.py` доказывает что **3 заявленные в презентации
оптимизации реально работают**:

| Оптимизация | Что проверяем |
|-------------|---------------|
| Батч-инференс (×10) | 16 × `/infer_raw` против 1 × `/infer_batch` |
| Параллельная загрузка (×7.5) | 16 объектов последовательно из MinIO против 8-поточно |
| Skip белых патчей (−75%) | время инференса на «белых» vs «контентных» патчах |

## Запуск

Стек должен быть запущен (`docker compose up -d`).

```bash
cd backend/benchmarks
pip install -r requirements.txt
python run_benchmarks.py
```

Если адреса другие:
```bash
python run_benchmarks.py \
    --inference http://188.126.62.18:18500 \
    --minio-host 188.126.62.18:19000
```

Если MinIO снаружи недоступен — пропусти его:
```bash
python run_benchmarks.py --skip-minio
```

## Вывод

В консоль — табличка с медианными временами и коэффициентами ускорения.
В файл `bench_results.json` — структурированные данные (для графиков в Excel/Grafana).

Пример вывода:

```
[1/3] Батчинг инференса (16 патчей)
----------------------------------------------------------------------
  Последовательно (16 × /infer_raw):     5.42 c   [min  5.31 / max  5.61]
  Батчем          (1 × /infer_batch):    0.58 c   [min  0.55 / max  0.62]
  → УСКОРЕНИЕ: ×9.34
```

Эти числа можно **прямо в презентацию** как доказательство.

## Зачем это рецензенту

Один из стандартных вопросов на защите: «А чем подтверждается, что ваша
оптимизация реально ускоряет? Есть бенчмарки?»

Ответ: «Да, на работающем стеке — вот файл `bench_results.json` и
методика измерения. Шум устранён медианой из 3 прогонов; не синтетика
рядом со стендом, а реальные HTTP-вызовы в живой инференс-сервис».
